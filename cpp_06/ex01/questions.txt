1. Conceptual Questions
About Serialization:

"What is serialization?"

Answer: Converting data into a format that can be stored or transmitted. Here, we convert a pointer (memory address) into a number.


"Why would you need to serialize a pointer?"

Answer: To store it, send it over network, save to file, or do operations that require numbers instead of pointers.


"What's the difference between serialize and deserialize?"

Answer: serialize converts pointer → number, deserialize converts number → pointer. They're inverse operations.




About reinterpret_cast:

"Why do you use reinterpret_cast here?"

Answer: Because we're converting between completely unrelated types (pointer ↔ integer). We're reinterpreting the same bits as a different type.


"Could you use static_cast instead?"

Answer: No! static_cast can't convert pointers to integers. You need reinterpret_cast for this.


"Is reinterpret_cast safe here?"

Answer: Yes, in this specific case. We're converting pointer → uintptr_t → pointer, which is guaranteed to work and give us back the original pointer.




About uintptr_t:

"What is uintptr_t?"

Answer: An unsigned integer type that's guaranteed to be large enough to hold any pointer. It's the correct type for storing addresses as numbers.


"Why not use unsigned long or int?"

Answer: Because they might not be big enough on all systems. uintptr_t is guaranteed to fit any pointer on any platform.


"What if uintptr_t isn't available?"

Answer: On older C++98 systems without stdint.h, you can use unsigned long as a fallback (though it's less portable).




2. Design Questions
About the class structure:

"Why is the constructor private?"

Answer: The subject says the class should not be initializable. We only use static methods, so we don't need objects.


"Why make the Orthodox Canonical Form private?"

Answer: To satisfy both requirements: have OCF (general rule) and prevent instantiation (exercise requirement).


"Could you create a Serializer object?"

Answer: No, because all constructors are private. You can only use the static methods directly on the class.


"Why are the methods static?"

Answer: Because they don't need any object state. They just perform a conversion operation that doesn't require member variables.




About the Data struct:

"Why did you use a struct instead of a class?"

Answer: Either works! struct is convenient because members are public by default, which is fine for simple data containers.


"What's in your Data struct?"

Show them and explain: "I included [members you chose] to demonstrate the serialization works with actual data."


"Does the Data struct need OCF?"

Good question! Technically yes for best practice, but often evaluators accept simple structs without it for this exercise.




3. Testing Questions
About your tests:

"Show me your test output"

Run your program and show that the pointers match after serialize/deserialize.


"How do you verify it works?"

Answer: By checking that the original pointer and the deserialized pointer are equal (same address).


"What happens to the data during serialization?"

Answer: Nothing! The object stays in memory. We're just storing its address as a number. The data itself doesn't move or change.
